# Huginn

Huginn is the shared work whiteboard for Metta ("vinnuborð Mettu"). Three participants read and write the same place: Heimir (decisions, running things), Árni (design, modules, specs in Markdown and HTML prototypes, never code) and Claude (analysis, plans, building, as its own service user). It replaces the Pending section of the metta2 CLAUDE.md, WhatsApp hand offs and memory notes as the single source for what is open. Live at **huginn.pro** (Vercel).

The old Trello style board, inbox, runes and Meta social planner are gone from the code. The repo, the name, login and the Supabase project stay.

Design spec: `docs/superpowers/specs/2026-10-31-huginn-vinnubord-design.md`; plan 5 spec: `docs/superpowers/specs/2026-11-01-stada-ur-gognum-design.md`. Plans: `docs/superpowers/plans/2026-10-31-vinnubord-{1-grunnur,2-bord,3-cli,4-skyndigreining}.md` and `docs/superpowers/plans/2026-11-01-stada-ur-gognum.md` and `docs/superpowers/plans/2026-11-01-handtok-breytt.md`.

## Tech Stack

- **Frontend:** React 19 + Vite 6 + TypeScript
- **Styling:** Tailwind CSS 4 (via `@tailwindcss/vite`) with `huginn-*` color tokens in `@theme` in `src/index.css`. No `tailwind.config.ts`.
- **Backend:** Supabase (Postgres, Auth, RLS, Realtime, Storage)
- **Routing:** React Router v7
- **i18n:** `react-i18next`
- **Tests:** vitest, `src/**/*.test.ts` (pure logic in `src/vinnubord/lib/`), `cli/**/*.test.mjs` (CLI pure logic and parity with the web) and `supabase/functions/**/*.test.ts` (`lib.ts` of the edge function, which stays import free and Deno free so vitest can load it). `jsdom` is a dev dependency for the Markdown sanitizer test only (`// @vitest-environment jsdom`).
- **PWA:** `vite-plugin-pwa` auto update service worker, manifest description "Vinnuborð Mettu"
- **Markdown:** `marked` and `dompurify` render Markdown in the panel reader. Loaded lazily (`Markdown.tsx` and `FileReader.tsx` are lazy chunks, and nothing the board imports eagerly imports `lib/markdown.ts`), so the board bundle does not carry them. No other UI libraries, icons are inline SVG.
- **Image pipeline:** `sharp` via `scripts/build-brand-assets.mjs`
- **Browser scripts:** `playwright` is a devDependency for `scripts/hg-shots.mjs` only (`npm run shots:hg`), nothing in `src` imports it. It needs `npx playwright install chromium-headless-shell` once.

### hg_ tables (migration 0001)

Every table except `hg_projects` carries `project_id`. RLS on all of them goes through `hg_is_participant(project_id)` (security definer). All participants of a project read and write everything in it, no roles.

- `hg_projects` : slug, name, repo_path, context_bundle. Created through MCP or service role. The insert policy needs the creator to already be a participant, so there is no working web insert path (ruling R1).
- `hg_participants` : user_id, display_name, short (H, Á), is_service (the Claude user).
- `hg_packages`, `hg_modules` : fixed board structure. Modules belong to a package, have status_line, color, is_ghost. `color` is a tone name or a `#rrggbb` hex; the metta modules carry the metta module colors (`--color-m-*` in metta2_new `src/index.css`) since 2026-11-01. Kiosk, Öryggisfundir, Ábendingar and most of Þvert á allt and Sala og samstarf have no metta color and keep a tone.
- `hg_items` : the things that move. status in new, waiting, ready, building, parked, done, dropped. `waiting_on` points at a participant. tags, pos_x, pos_y, next_step, next_prompt, closed_at, and since 0016 `keywords text[]` (hidden search words, see Key Patterns).
- `hg_plans` (todo, building, done), `hg_rulings` (on a plan), `hg_files` (since 0014 also `updated_at`, `updated_by`, one row per `(item_id, repo_path)`), `hg_questions`, `hg_actions` (since 0012 also `updated_at`, `updated_by`, `cancelled`, `cancel_reason`), `hg_comments` (on item or module), `hg_tags` (since 0016: the project's fixed tag list, `(project_id, name)` unique case insensitively, participant RLS).
- `hg_events` : timeline, written only by security definer triggers (migration 0003), select only for participants.
- `hg_reads` : read marks per (item_id, user_id).
- `hg_views`, `hg_view_positions` (migration 0011): saved board views, filter as `{ tones, packages, tags }` json (empty means all), and card positions per view keyed `(view_id, item_id)`. Realtime on both.
- `hg_view_pack_positions` (migration 0013): pack column positions per view keyed `(view_id, package_id)`, same rule as `hg_view_positions`. Realtime.
- `hg_zones`, `hg_view_zone_positions` (migration 0017): boxes (title up to 60, `color` one of the five tones, `note` up to 200, `pos_x`, `pos_y`, `w`, `h` with minimum 160 by 120) and their position per view keyed `(view_id, zone_id)`. Participant RLS, composite project keys, realtime. No events and no `updated_at`: a box is arrangement, not a work item.

Helpers: `hg_is_participant(p_project)`, `hg_service_user(p_project)`. Realtime publication includes all hg_ tables except projects and participants.

### Migrations

Files live in `supabase/migrations/` (see the README there). Applied with the Supabase MCP tool `apply_migration`, name = file name without `.sql`. Never `supabase db push`. Files are applied in order and never edited after they are applied. Any DROP or DELETE is run by hand by Heimir in the SQL editor.

- `0001_hg_schema` : applied.
- `0002_hg_rls_hardening` : applied by Heimir in the SQL editor on 2026-10-31 (the MCP connector declines DROP statements). Not listed in `supabase_migrations.schema_migrations`.
- `0003_hg_triggers_storage` : applied through MCP. Adds updated_at touch on items and plans, the `hg_events` log written by security definer triggers, answering the last open question moves the item to waiting with `waiting_on` = service user, `closed_at` set on entering done/dropped and cleared on reopen, author stamping from `auth.uid()` (created_by, asked_by, uploaded_by, user_id, updated_by, answered_by, done_by), and the private bucket `hg-files` (50 MB limit) with storage policies `hg_files_storage_select/insert/delete` through `hg_can_access_path(name)`. There is no storage UPDATE policy, so uploads must use `upsert: false`.

## Internationalization

Two UI languages: Icelandic (default) and English, through `src/shared/i18n/`.

- `en.json` is the hand maintained source. `is.json` is generated by `npm run translate` (OpenRouter Gemini, hash diffed per key, cache in the gitignored `.is.cache.json`). Hand edits to `is.json` stick while the English source is unchanged and the key is in the cache; a key with no cache entry (a fresh checkout, or a hand edit never cached) is retranslated and the hand edit lost, so check the `is.json` diff after every translate run. Keys in `is.json` are emitted alphabetically, so insert manual additions in alpha order.

## Key Patterns

- **Realtime board data.** `useBoardData` loads the whole board through `lib/api.ts` and subscribes to hg_ tables filtered on `project_id`. Channel names use `crypto.randomUUID()` to avoid collisions between hook instances. Realtime DELETE events are not delivered to `project_id` filtered subscriptions under RLS (Supabase sends only the primary key for a delete, so the filter cannot match and replica identity full would not help): a deleted row disappears on other open boards only at their next change or reload. The deleting client reloads itself.
- **Pure logic is tested.** Anything that decides status, counters, filters, upload rules or the continuation prompt lives in `src/vinnubord/lib/` without React or Supabase, with a vitest file next to it. Test files import from `vitest` explicitly because `tsc -b` compiles `src`.
- **Gesture contract.** `useViewport` owns pan, wheel zoom, pinch, fling and double tap on the board element. It keeps the live view in `viewRef` and writes the world transform, `--hg-z` and the zoom label directly (`apply`); React state follows at gesture end (`sync`: last pointer up or fling stop, 120 ms after the last wheel step, end of a glide, a press that stops motion, `setView`). `sync` also writes the settled zoom `--hg-zs` on the world layer (so does a world that mounts later), which the far labels read instead of `--hg-z`. `Wires`, `useCardDrag` and `placeNew` read `viewRef`, never the `view` state, and nothing in React writes the world transform. It exposes a `gestureRef` (`pinching`, `dragPointer`, `active` while a pan, pinch or fling moves the view, `stoppedMotion`). Touch on a button, link or label inside the board (module cards, pack titles) pans past `CARD_PAN_SLOP` and pinches like a card, only form fields and `[data-no-pan]` are ignored; mouse still ignores buttons. A one finger touch pan released faster than `FLING_START` flings (`lib/fling`, velocity from the last 80 ms), a pinch or `prefers-reduced-motion: reduce` never flings, a new pointer stops it. Two taps on the empty board within 300 ms and 24 px (straight line distance) zoom in 2x around the point; mouse gets neither. A press that stops a fling or a glide never taps or clicks, on any target (`stoppedMotion` set in a native capture `pointerdown`, `useCardDrag` skips `onTap`, the click that follows is swallowed). Zoom buttons, fit and pack titles glide over `--hg-dur-view` (`animateTo`). The start view: when the board is narrower than 1024 px or the pointer is coarse the first load shows the first pack at zoom 0.8 (`startAtPack`), otherwise it fits everything. `useCardDrag` is bound on the world layer and runs first: mouse lifts a card on press and drags past 3 px; touch lifts after a 350 ms long press, and a touch that moves more than 10 px before that gives up and the viewport pans instead. Two touches always pinch, also with a finger on a card, and a pinch cancels a lifted drag and returns the card to its start. `useCardDrag` never calls `stopPropagation`, and card elements are `div role="button"` (not `<button>`) because the viewport ignores pointers on buttons. Drag only writes `pos_x` and `pos_y`, springs run in the Wires animation frame so wires read card rects after they moved. The same hook drags pack columns: the pack title button carries `data-grip="pack"`, the viewport treats a grip like a card, and a press on it follows the card rules (mouse drags past 3 px, touch after the 350 ms long press, a plain click or tap still fits the pack). The column moves with its modules (they are its children, modules stay locked in their order), `Board` writes the column's `left` and `top` directly and wakes the wires on each move, the drop saves at once (`updatePackagePosition` on the main board, `upsertViewPackPosition` inside a view, the view fixed at drop time like a card) and the column rests at the dropped place until the data shows it. The click that follows a drop is swallowed by the hook (window, capture phase, 500 ms), so a dragged title does not also fit.
- **Multi selection is mouse only.** `useMarquee` (bound on the board with `onPointerDownCapture`, so it runs before the card drag and the viewport and stops the press there) turns a Ctrl or Cmd primary mouse press into a marquee: the `.hg-marquee` div is written directly in screen space, every move converts it to world units and `selectInRect` in `lib/selection.ts` picks the cards whose box it touches and the packs whose title box it touches (Shift adds to the selection); while the box is drawn those elements get `.hg-card-pre` and `.hg-pack-pre` written straight on them (`onMarqueePreview`, no render) and the release puts the same result in state. A Ctrl click toggles one card or pack, a plain click on the empty board and Escape clear, and the click after a marquee or a toggle is swallowed so it never closes the panel. `Board` keeps the selection in state and `selectionRef`; when `useCardDrag` presses a member, `getTargetPos` snapshots every member's position (`groupStart`) and `groupMoves` moves them all by the grip's delta on every move, drop and cancel (cards through their springs and `onDrop`, packs through `movePack` and `dropPack`), so the saves follow the usual rules per member. A press outside the selection drags alone and clears it. `lifted` is the whole group while it drags (`draggingRef` is a set), chosen cards and pack titles carry `.hg-card-sel` and `.hg-pack-sel`. Touch gets no marquee, the long press already lifts one card.
- **Zones are arrangement, not data.** A box owns no cards: membership is geometry at press time (`zoneMembers` in `lib/zones.ts`: a card whose centre is inside, a pack whose title is inside), so a card dragged out simply stops belonging, and deleting a box moves nothing. The name is the grip (`data-grip="zone"`, the corner is `zone-resize`); a press on either follows the card rules (mouse drags past 3 px, touch after the 350 ms long press), and the move goes through the same group move as a Ctrl selection (a zone is a grip, never a member, `isMember` is false for it). Position is per view (`hg_view_zone_positions`, `zonePositionsOf`, a drag in a view never writes `hg_zones`), size is shared and always saved on `hg_zones`; a failed save rolls the pending back only when it still matches what was sent (`zoneSaveFailed`). The box is drawn under cards and packs (`--hg-zone-z`), so a name covered by a card cannot be pressed. Draw mode (`drawing` in `BoardPage`) takes the next press in capture phase like the marquee (`useZoneDraw`, combined in Board's `onPointerDownCapture`), ends after one box or on Esc, and writes no events.
- **Touch devices.** Everything for phones and tablets hangs on `(pointer: coarse)` and two breakpoints, so a mouse desktop looks and behaves as before. A `pointer: coarse` token block in `vinnubord.css` (after the reduced motion block) turns the blur tokens to `none`, makes surfaces nearly opaque and lightens shadows. `Wires` reads the same query live: no `shadowBlur`, pixel ratio at most `WIRE.coarse.dpr` (1.5), ambient sparks only on hot wires (selected or dragged card), and no glow stroke while `gestureRef.current.active`. Below 1024 px (`useMediaQuery`) `TopBar` shows one filter button (`.hg-filter-btn`, with the pick count) instead of the Pakki, Tögg and Sýn dropdowns, and it opens `FilterSheet`: a bottom sheet on a phone, a centred dialog on a tablet, holding the inline `ViewMenu` and `FilterMenu` (`inline` renders the chips with no dropdown, no outside click or Esc listener), "Hreinsa" and "Loka". The sheet closes by itself when the width passes 1024 px. Below 768 px (`useIsMobile`) the item panel is a bottom sheet: it is a fixed height (`100dvh` minus `--hg-sheet-top` and `--hg-safe-top`, so at full it clears the notch), opens at the `full` stop (`OPEN_STOP` in `lib/sheet`), and moves only by `transform: translateY(--hg-sheet-offset px)`, with stops full, half (45%) and closed and a flick rule (`snapSheet`). `PanelShell` writes `--hg-sheet-offset` (0 at full, never a unit, against the aside's own measured `offsetHeight`, read on entering narrow and on resize, never per move) and drags it from three surfaces: the handle (a tap toggles full and half), the head, and the body, where only a touch that starts at scroll top and goes down takes over (native non passive touch listeners with detach and cancel, so a cut short drag never leaves the sheet stuck); everywhere else the body scrolls. `--hg-sheet-top` is 48 px, which at full is the first top bar row, so a tap above the sheet closes it only at half; at any stop the 44 px close button (`.hg-sheet-close`, right end of the handle row) closes it, and presses on it are never a drag, a handle tap or a body takeover.
- **Safe areas and touch on pages.** `viewport-fit=cover` plus `black-translucent` put pages under the status bar and the notch, so every surface adds `--hg-safe-*` (board, bars, controls, sheets, settings page). Tailwind pages (Login, ResetPassword, AuthCallback, NoAccess, ErrorBoundary, LoadError) use the `safe-p-N`, `safe-top-N` and `safe-right-N` utilities from `src/index.css` instead of `p-N`, `top-N` and `right-N`. The emulator reports zero insets, so only a real iPhone in the installed PWA shows them.
- **Panel survives refetch.** `BoardPage` keys `ItemPanel` by item id, so tab, scroll and drafts live across realtime refetches and reset when another item opens. `markRead` runs on open and whenever a newer event by someone else arrives on the open item (`latestForeignAt` in `lib/reads.ts`). The server stamps `read_at`. Optimistic toggles (`useOptimisticToggle`) follow the live value when realtime brings it.
- **Unread comes from events, not `updated_at`.** `hg_unread` groups the viewer's unread events per item and kind, `summarizeUnread` in `lib/reads.ts` turns them into the card glow, the card's fresh line, the unread pill and the unread filter. The panel captures `readAtOnOpen` before marking so fresh rows stay marked until it closes. `hg_mark_all_read` marks every open item read. The card glow (`.hg-card-new`) is `fresh !== null`, and the fresh line (`freshLine` in `lib/cards.ts`) prefers "Nýtt verk", then the newest unread message by someone else (`freshComment`, read against the viewer's read mark), then the unread kinds.
- **The chat lives in `item.md`.** Comments on an item are its chat (Spjall tab, `lib/chat.ts`). The mirror writes them under `## Spjall` in `item.md`, and the `/huginn` skill in metta2_new reads that section when a session starts or takes an item and answers there with `huginn comment add <id> --body "..."`, also at session end when the session finished or answered something asked in the chat.
- **Views are a filter plus positions.** `itemsInView` in `lib/views.ts` decides which cards are drawn (tone through `countBucket`, package, tag; empty means all), and `BoardPage` feeds its result to the counters, the pack and module counts, the filter menus and `Board`. The local filter and search only dim inside it. A drag in a view writes `hg_view_positions` (the save target is fixed at drop time, so switching views within the debounce still saves to the view the card was dropped in) and never `hg_items`; a card without a view position shows at its main position. Pack columns follow the same rule through `hg_view_pack_positions` and `packPositionsOf`: a pack dragged in a view moves in that view only, and one without a row rests at `hg_packages.pos_x`/`pos_y`. The active view id lives in `localStorage` `hg.view.<projectId>` (per browser, `useActiveView`), a stale id falls back to the main board. `ViewMenu` saves a fully ticked group as "all" (`normalizeViewFilter`, spec 5.4), which also includes untagged and moduleless items. Deleting a view is a normal participant action in the menu and cascades its positions.
- **The list reads the same card model as the board.** `cardModels` in `lib/cards.ts` runs once in `BoardPage` and feeds both `Board` and `listRows` (`lib/list.ts`), so the list and the board always show the same items and counts. The drawer lives outside `.hg-board` and never touches the viewport, springs or wires. A row calls `reveal`, which glides the card into the free area (`freeRect` in `lib/geometry.ts`: the list on the left, the panel on the right and, on a phone, the half sheet below, so `h * (1 - SHEET_HALF)` is reserved at the bottom and the card is centred in the upper 45% of the board; zoom never drops under 0.8); `peek` lights a card from a hovered or focused row without a render (`hg-card-peek` written on the element, cleared by `peek(null)` when the pointer or focus leaves the list body and by every way of closing the list); every fit (`Sýna allt`, pack title, first load) pads the free area, and the first pack start on a narrow or touch board (`startAtPack`, whose `left` argument is the open list's width) starts right of the list. The pack sorted list puts items of a module that no pack column draws (no package, or a missing one) under "Án módúls". The open state and sort are stored per browser (`hg.list.<projectId>`, `useListPrefs`) on wide boards only; below 1024 px the state is in memory, starts closed and a row pick closes it. Esc closes the list only when no field, side panel, new item sheet, filter sheet or dropdown is open. Closing the list by its close button, Esc or the top bar button moves focus that was inside it to `.hg-list-btn`; a narrow row pick leaves focus to the panel. A selected item or open module that leaves the data clears its id, so `panelOpen` never pads for a panel that is gone.
- **Search is one folded index.** `searchIndex` in `lib/search.ts` builds one string per item from title, text, tags, files, questions, actions, chat and keywords, and `foldSearch` lowercases and strips diacritics (the Icelandic letters such as ð and þ stay themselves) so `syning` finds `sýning`. `filters.ts` matches the search box against that index; the local search only dims inside the active view. Ctrl or Cmd and F opens the search box instead of the browser's, on the board and in a panel, and Esc clears it; while the reader is open Ctrl+F goes to the browser's own find, which searches the document.
- **Tags are a fixed list.** `hg_tags` is the project's list; an item's `tags` hold names from it (checked by 0016b). The list is edited only in the project settings or with `huginn tag add`; new items and `hg-analyse` choose from it. Rename, merge and delete go through the three RPCs, which are silent (`hg.silent`): no stamp, no `item.updated`, nothing turns unread. A tag name is normalised by `normalizeTag` (web `lib/tags.ts` and CLI `write.mjs`, kept equal by the parity test): lower case, at most 40 characters, no comma. The count beside a tag covers the board window only (closed items older than 90 days are not loaded).
- **Keywords are hidden and silent.** `hg_items.keywords` are search words the user never sees: not on the card, not in the panel. They are written by `hg-analyse` and by `huginn item create|set --keywords`, appear as the `Leitarorð` line in `item.md`, feed the search index, and a write to them touches no stamp and logs no event.
- **Counter pills filter by count bucket.** `countBucket(item, actions, viewerId)` in `status.ts` decides which pill an item counts in (new, mine, others, build, parked), `countsFor` uses it, and `BUCKET_TONE` maps a bucket to the tone the filter matches, so a pill number and its filter always agree. Card color still comes from `itemTone`. A closed item (`!isOpen`) has bucket `null` and counts in no pill; `cardModels` matches it with a `null` tone (its own tone stays `stone`), so it matches tag, package, unread and search filters but fails any tone filter.
- **Analysis rules.** `hg-analyse` never touches an item that is not `new` (the write is gated on status and on `updated_at`, with one re-merge). The author's body is kept verbatim under `## Upprunalegur texti`, the author's module and tags win over the model's. Success writes `analysis.done`, failure writes `analysis.failed` with error and stage and leaves the item `new`; both show in the item history. Skips (not found, not new, locked, created by the service user) are console only, no board event. Known gap: a silent tag rename, merge or delete does not move `updated_at`, so an analysis running at that moment can write the old tag name back (after 0016b that write fails as `analysis.failed` and the item stays `new`).
- **Status is stored, not computed.** Claude and the participants move status. Two triggers move it for them: answering the last open question (0003) and a plan entering building or done (0008, which since 0009 also clears the spent next step and prompt). Dragging only arranges the board.
- **Closed cards linger three days.** `isOpen(item)` (status not done or dropped) decides everything about counts, wires and the panel; `isOnBoard(item, now)` is `isOpen` or closed within `CLOSED_LINGER_DAYS` (3) of a parsable `closed_at`. `now` is a parameter with a default, so never write `items.filter(isOnBoard)` (the index becomes the clock and every closed item stays); pass an arrow with an explicit clock or use `isOpen`. `BoardPage` takes one clock per board load (`useMemo(() => Date.now(), [data])`) and feeds `itemsInView`, `viewCounts`, `cardModels` and `boardCount`, so the three day rule leaves on the next data change, not on the clock. `CardModel.closed` draws the faded card, and the list puts closed cards last in their module (status sort: a "Lokið" bucket).
- **Folding is per browser.** `hg.packs.<projectId>` in `localStorage` (`lib/packs.ts`, `useCollapsedPacks`) holds the folded pack ids. A folded pack hides its modules and cards from the board only (wires, counts and the list are untouched, `foldLine` is the one line). A drop of a folded pack moves its hidden cards by the same delta (`savePosition`, no spring), kept per item and view until the reload spends it (`lib/carry.ts`, so two quick drops never read stale data); picking a hidden card from the list or creating an item in the pack opens the pack first.
- **Raða is selection only.** `SelectionBar` shows with two or more selected cards (`selection.cards`); Raða runs `arrangeGrid` (`lib/arrange.ts`, pure: rows found by a tolerance on y, a grid centred on the selection) and writes through `onDrop` like a drag, so the saves follow the usual view rules. Afturkalla writes the previous positions through `onDrop` for 8 seconds and is cleared by any change of selection or view. The wait for a card save uses `lib/pending.ts` (`Pending.via` holds the points sent, so a late echo of an earlier drop is not taken for a foreign move).
- **"Halda áfram" is a pointer, not a copy.** `buildContinuationPrompt` in `lib/continuation.ts` gives the item id and title, the source and an instruction to run `huginn sync` and read the mirror folder (ends with the first 6 characters of the id), then `next_prompt`. Everything else lives in the mirrored `item.md`. The run command (`resumeCommand`, Opus when the item is ready or building or a plan is open) shows beside the button and is not copied.
- **Same repo path is the same file.** A file with a `repo_path` is one row per item and path. `putFile` in `cli/lib/ops.mjs` looks the row up by item and normalised path (`normalizeRepoPath` in `cli/lib/write.mjs`: backslash, `./`, doubled slashes, spaces), compares bytes when the size matches (identical writes nothing, a download error counts as different), uploads the new object, updates the row guarded by `.eq('storage_path', old)` (a concurrent replace that loses fails) and removes the old object (a failed remove only warns; the old object is touched only when `storagePathOk` accepts its path). `fileStamp` and `sortFiles` in `lib/files.ts` order the Files tab by the later of `created_at` and `updated_at`, and the fresh mark reads the stamp and `updated_by`. Web uploads carry no path, so they never replace. Own events never count as unread, so only the other participants see "+1 skjal" after replaces. A note on the file (`hg_files.note`, `normalizeNote`) is separate from the object: `file add --note` writes it on add, replace and unchanged, `file set` writes it alone, and a replace without `--note` keeps the old note; a note write moves no stamp and logs no event.
- **The reader is one id in BoardPage.** `readerFileId` in `BoardPage` is the single source for the reader: it widens the side panel (`.hg-panel-wide`, `.hg-toast-panel-wide`), makes the free area (`freeRect`) use the wide panel, hides the list drawer (`listShown = listPrefs.open && !readerOpen`, the stored `hg.list.<projectId>` pref never changes), and makes Esc close the reader before the panel. `ItemPanel` renders the reader as a sibling of the `.hg-pn` tree, which gets `hidden`, so tab, scroll and drafts survive; `FileReader` is keyed by `storage_path`, and the file row is looked up live, so a realtime replace of the same repo path reloads the new text. The Lesa and Md mode is `readerMode` state in `ItemPanel` (kept between files while the panel is open, not between openings); txt files have no switch. Heading ids (`hg-h-N`, only top level h1 to h3, in order) exist only when the reader asks for them (`renderMarkdown(source, { headingIds: true })`), `outline` in `lib/markdown.ts` walks the same tokens, and the toc shows with two or more headings in Lesa mode (`showToc`). `marked` and DOMPurify stay out of the board bundle: `FileReader` is `lazy` and `lib/reader.ts` is pure. Sækja goes through `downloadFile` (blob, object url revoked 60 s after the click, because a save picker can hold the download) because Supabase signed urls double encode Icelandic file names.
- **Actions are the only pending list.** Summary, body and prompts never list what is left for whom; the card chip ("N hjá þér"), the folded action list and `pull` all read `hg_actions`. The `/huginn` skill (metta2_new) states the rule. An action that became wrong is changed with `action set`, one that no longer applies is cancelled with `action cancel`; cancelled is closed (`done_at` set, `cancelled` true), so nothing that reads `done_at` changes.
- **Board sizes have a CLI copy.** Changing pack, module or card tokens (`--hg-pack-*`, `--hg-module-*`, `--hg-card-*` sizes) means updating `base` in `cli/lib/write.mjs`; `parity.test.mjs` fails until they match. `base.cardBySize` and `base.cardModuleGap` copy `--hg-card-by-size` and `--hg-card-module-gap`, and `CARD_STAMP_DAYS` in `write.mjs` must equal the one in `lib/cards.ts` (the stamp row is counted only within 7 days, the module line always when the card has a module, tags never). `base.touch` copies `--hg-touch`, because the pack title button is at least that tall and the pack head estimate takes the larger of it and the title line. A whole board re-layout is data, not code: write `pos_x`/`pos_y` of packages and items as a participant (a pos only update keeps `updated_at`), using `estimateModuleHeight` and `estimateCardHeight` from `cli/lib/write.mjs` for sizes.
- **CLI copies web logic.** `cli/` is plain Node ESM and cannot import the TS in `src`, so it copies the rules it needs as `.mjs` (status names, `isOpen`, `isOnBoard` and `CLOSED_LINGER_DAYS` (a lingering closed card is an obstacle for `placeNewCard`), `waitsFor`, upload limits, `placeNewCard`, card sizes from `--hg-*` tokens) and `cli/lib/parity.test.mjs` asserts they match `src/vinnubord/lib` and `vinnubord.css`. Change both sides together. It signs in as a normal user with the anon key (the Claude service user in Heimir's setup), so RLS and the triggers apply; credentials live in `~/.huginn/`, never in a repo. Flags are strict: write commands and `sync` reject unknown flags.
- **ErrorBoundary** wraps the router, render errors show a panel instead of a blank screen.

## End-of-session rituals

When I say "end of session", "end session", "wrap up", "I'm done for now", or similar, treat it as a session-closing trigger and execute one of the procedures below. If unclear which applies, ask me before acting. The goal: leave things clean so I can `/clear` the conversation with no loose ends.

### Stable checkpoint (build green, no half-done edits, ready to /clear)

1. Run `npm run build`. Report any errors before proceeding. Only continue once build passes.

2. Update CLAUDE.md sections that map to what changed this session. This is a reference doc, not a progress log — there is no "What's built" list to append to. Touch only the sections that were actually affected:
   - New route added → update the Routes section
   - New table / RLS change / storage bucket / realtime addition → update the Supabase section (or equivalent)
   - New edge function → update the Edge Functions section
   - New env var → update the env-var list under Commands or Tech Stack
   - New convention discovered from a bug fix → update Conventions / Key Patterns / relevant section
   - Design system change → update Design System
   - New deploy quirk → update Deployment

   Skip any section that was not affected. Match the project's existing tone, formatting, and heading style.

3. Do NOT add a "Recent changes" log to CLAUDE.md. History lives in git; CLAUDE.md stays a reference snapshot of current state. Per plan handovers in `docs/progress/NN-<plan>.md` are allowed (see Conventions), session logs are not.

4. Report back with:
   - Which CLAUDE.md sections you edited (section name + nature of change, not full diff)
   - Any new env var or secret the deploy target needs before the next deploy
   - Any uncommitted files the session left behind

Commit the CLAUDE.md update and push once the build is green.

### Mid-work handoff (bug unresolved, blocked, or stopping mid-flight — NOT at a checkpoint)

Write a resume note at `docs/session/YYYY-MM-DD-<short-topic>.md`. Create the `docs/session/` folder if it does not exist, and add `docs/session/` to `.gitignore` if it is not already there. Use absolute paths throughout - the next session may have a different working directory.

Structure:

```
# YYYY-MM-DD Resume: <topic>

## In-flight
What feature or bug is being worked on, what it is for, why it matters.

## What was done this session
Concrete changes with file:line references (absolute paths). Include migrations drafted even if not applied. Be specific.

## Running state
- Background processes: shell IDs + what they are + how to kill - or "none"
- Dev servers / ports: url + port - or "none"
- Open worktrees / branches beyond main - or "none"

## What's blocking / unknown
What stopped progress. Paste exact error messages verbatim. For design questions, state the options considered.

## Next 2-3 actions on resume
Numbered, concrete steps. Not "figure out the bug" — rather "1. Retry X; 2. read the error; 3. match against guesses below."

## Paths already tried (do NOT redo)
What was attempted that did not work.

## Files touched but not finished
Files with pending edits (absolute paths).

## Context the next session needs
Deploy state (migrations applied, edge functions deployed), env vars set in the deploy target, any uncommitted or unpushed local state.

## Pick up here
One sentence: the single most likely first action for a fresh agent on resume.
```

After writing the file, report back with:
- Path to the resume note
- Any uncommitted or unpushed state that would confuse the next session
- Any background processes still running that the next session should know about

Do not commit. Do not revert anything.

### Session-break decision guide

| Break length | What to do |
|---|---|
| < 1 hour | Leave the conversation open. 1h cache TTL covers it. |
| Overnight, at a checkpoint | Run the stable-checkpoint procedure, then `/clear` |
| Overnight, mid-work | Run the mid-work handoff procedure, then `/clear` |
| Weekend or longer | Always mid-work handoff + `/clear`, never leave open |
