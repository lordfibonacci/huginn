# Kassar: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boxes ("kassar") on the whiteboard: a named, coloured rectangle with an optional note that every participant sees, that has its own position per view, that moves with the cards and pack titles inside it when its name is dragged, and that is resized from its bottom right corner.

**Architecture:** Migration 0017 adds `hg_zones` and `hg_view_zone_positions` with the same RLS, stamp trigger, composite project keys and realtime as the view tables. The web gets a pure `lib/zones.ts` (rects, members, title rule), a `Zone` component drawn in the world layer under packs and cards, two new drag kinds in `useCardDrag` (`zone` moves the box and its members through the existing group move, `zoneResize` writes width and height), a `useZoneDraw` hook that takes the next pointer press in draw mode the way `useMarquee` takes a Ctrl press, a `ZonePanel` in the `PanelShell` for name, colour, note and delete, and a "Kassi" button in the top bar. Nothing in the CLI, the mirror or `hg-analyse` changes.

**Tech Stack:** React 19 + TypeScript, vitest, react-i18next, Supabase (Postgres, RLS, Realtime), Supabase MCP for the migration.

**Spec:** `docs/superpowers/specs/2026-11-04-kassar-og-tiltekt-design.md`, sections 4.1 to 4.3, 5, 6 and 8. Plan 16 (tiltekt) builds sections 4.4 to 4.6 after this plan.

## Review Focus

1. A second finger during a touch draw: the draft disappears, draw mode ends, no box is created, and the two fingers pinch the board as usual. Pinned in Task 6 (manual check 4).
2. A box dropped inside a view: `hg_zones.pos_x` and `pos_y` do not move, a `hg_view_zone_positions` row is written, and `hg_items.updated_at` of a member card does not move when it was dropped at its own place. Pinned in Task 8 (smoke 14 steps c and e).
3. A resize dragged below the minimum: the box stops at 160 by 120 on screen (`clampZoneSize`) and the database refuses a smaller row with `23514`. Pinned in Task 2 (`clampZoneSize` test) and Task 8 (smoke 14 step b).
4. A box name of only spaces: `normalizeZoneTitle` returns `Kassinn þarf nafn.`, Vista stays disabled and nothing is written. Pinned in Task 2 (`normalizeZoneTitle` test) and Task 7 (manual check 2).
5. A card whose centre lies exactly on the box border is a member and moves with the box; a card whose centre lies one unit outside is not. Pinned in Task 2 (`zoneMembers` test).

```sql
-- 0017_hg_zones
-- Boxes on the whiteboard (spec 2026-11-04-kassar-og-tiltekt-design.md, 4.1):
-- a named, coloured rectangle with an optional note, shared by the project's
-- participants, with its own position per view like cards (0011) and pack
-- columns (0013). The size is shared, the position is per view. No events,
-- no updated_at: a box is board arrangement, not a work item, like a view.
-- Composite project keys as in 0011b.

create table hg_zones (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz default now(),
  project_id uuid not null references hg_projects(id) on delete cascade,
  title text not null,
  color text not null default 'lilac',
  note text,
  pos_x int not null,
  pos_y int not null,
  w int not null,
  h int not null,
  created_by uuid,
  constraint hg_zones_title_check check (btrim(title) <> '' and char_length(title) <= 60),
  constraint hg_zones_color_check check (color in ('gold', 'lilac', 'coral', 'teal', 'stone')),
  constraint hg_zones_note_check check (note is null or char_length(note) <= 200),
  constraint hg_zones_size_check check (w >= 160 and h >= 120),
  constraint hg_zones_id_project_key unique (id, project_id)
);

create index hg_zones_project_idx on hg_zones (project_id);

create table hg_view_zone_positions (
  project_id uuid not null references hg_projects(id) on delete cascade,
  view_id uuid not null references hg_views(id) on delete cascade,
  zone_id uuid not null references hg_zones(id) on delete cascade,
  pos_x int not null,
  pos_y int not null,
  primary key (view_id, zone_id),
  constraint hg_view_zone_positions_view_project_fk
    foreign key (view_id, project_id) references hg_views (id, project_id) on delete cascade,
  constraint hg_view_zone_positions_zone_project_fk
    foreign key (zone_id, project_id) references hg_zones (id, project_id) on delete cascade
);

create index hg_view_zone_positions_project_idx on hg_view_zone_positions (project_id);
create index hg_view_zone_positions_zone_idx on hg_view_zone_positions (zone_id);

alter table hg_zones enable row level security;
alter table hg_view_zone_positions enable row level security;

do $$
declare
  t text;
begin
  foreach t in array array['hg_zones', 'hg_view_zone_positions'] loop
    execute format(
      'create policy %I on %I for select to authenticated using (hg_is_participant(project_id))',
      t || '_select', t);
    execute format(
      'create policy %I on %I for insert to authenticated with check (hg_is_participant(project_id))',
      t || '_insert', t);
    execute format(
      'create policy %I on %I for update to authenticated using (hg_is_participant(project_id)) with check (hg_is_participant(project_id))',
      t || '_update', t);
    execute format(
      'create policy %I on %I for delete to authenticated using (hg_is_participant(project_id))',
      t || '_delete', t);
  end loop;
end
$$;

-- created_by from auth.uid(), kept on update (same rule as hg_views and hg_tags)
create trigger hg_zones_stamp_trg
  before insert or update on hg_zones
  for each row execute function hg_views_stamp();

alter publication supabase_realtime add table hg_zones, hg_view_zone_positions;
```
