# Skjöl (lýsing, sækja, lesari): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every file on an item carries a one sentence note, every file row and the reader get Sækja, and md and txt files open in a wide reader with a table of contents, a readable measure, a Lesa / Md switch and Afrita allt.

**Architecture:** Migration 0015 adds `hg_files.note`; nothing else in the database changes, so a note write moves no stamp and logs no event. The note rule (`normalizeNote`, `NOTE_MAX`) is pure in `lib/upload.ts` and copied to `cli/lib/write.mjs` under parity. The reader is a lazy component (`FileReader`) that replaces the item panel content while `BoardPage` holds `readerFileId`; `BoardPage` derives from that one value the wide panel (`PanelShell wide`), the free area (`Board panelWide`), the hidden list, the toast offset and the Esc target. Heading ids and the outline come from `lib/markdown.ts`, only when asked for.

**Tech Stack:** React 19 + TypeScript, vitest, react-i18next, marked 18 + DOMPurify (lazy chunk), Supabase (Postgres, Storage signed urls), Node ESM CLI, Deno edge function, Playwright (`npm run shots:hg`).

**Spec:** `docs/superpowers/specs/2026-11-03-skjol-design.md`

## Global Constraints

- One migration, `0015_hg_file_note`, one statement: `alter table hg_files add column note text;`. No trigger, function or policy changes. Applied through the Supabase MCP `apply_migration` (name without `.sql`), never `supabase db push`.
- **Never a coloured left border, stripe or bar** on a file row, a toc line or the reader. The active toc line is bold and `--hg-ink`, nothing else (spec section 2, and-markmið).
- No em dashes or hyphen dashes as punctuation anywhere: code comments, copy, docs, commit messages. Commas, periods or colons.
- Icelandic UI copy. New i18n keys go in `en.json` by hand under `vinnubord.*`, `npm run translate` regenerates `is.json`, then check the `is.json` diff and correct the Icelandic by hand (keys alphabetical). Validation reasons are Icelandic strings in code, like `validateUpload`.
- Rules below the token block in `vinnubord.css` read only tokens. New values are tokens in `:root`, in the section the task names. Touch overrides go in the `pointer: coarse` block.
- `marked` and DOMPurify stay out of the board bundle: `FileReader` is `lazy`, and nothing imported eagerly by `ItemPanel` or `BoardPage` imports `lib/markdown.ts`.
- Pure logic in `src/vinnubord/lib/` with a vitest file beside it; test files import from `vitest` explicitly. CLI copies in `cli/lib/*.mjs` with `parity.test.mjs` pinning them.
- Branch `vinnubord-13` off `main`. Commit prefixes `feat(vinnubord):`, `test(vinnubord):`, `docs(vinnubord):`, `chore(vinnubord):`, with the `Co-Authored-By:` trailer of the model that authored the commit.

### Task 4: Markdown heading ids and outline

**Files:**
- Modify: `src/vinnubord/lib/markdown.ts`
- Modify: `src/vinnubord/lib/markdown.test.ts`
- Modify: `src/vinnubord/components/Markdown.tsx`, `src/vinnubord/components/MarkdownView.tsx`

**Interfaces:**
- Produces, exported from `lib/markdown.ts`:
  - `renderMarkdown(source: string, options?: { headingIds?: boolean }): string`: without options the output is byte for byte what it is today. With `headingIds` every `h1`, `h2`, `h3` gets `id="hg-h-N"`, N counting from 1 over those three levels in document order; `h4` to `h6` get none.
  - `export type Heading = { id: string; level: 1 | 2 | 3; text: string }`
  - `outline(source: string): Heading[]`: the same headings in the same order with the same ids, `text` is the plain text of the heading (inline tokens joined on their `text`, so `**Bold** and \`code\`` gives `Bold and code`).
- `Markdown` and `MarkdownView` take `headingIds?: boolean` and pass it on.

Implementation note (not a choice): use a `new Marked()` instance per call (or per module, reset the counter per call) with `renderer.heading` overridden, so the shared `marked` default stays untouched for the status tab; `outline` uses `marked.lexer(source, { gfm: true })` and walks top level tokens of type `heading` with `depth <= 3`, flattening `token.tokens` to text.
