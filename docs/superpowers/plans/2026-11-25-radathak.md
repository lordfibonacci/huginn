# Raðaþak: loadBoard reads every list in pages. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `loadBoard`, on the web and in the CLI, returns every row of every list, however many there are, instead of the first 1000.

**Architecture:** One pure pager, `fetchAll`, asks for 1000 rows at a time with `count: 'exact'` and stops when it holds as many rows as the server counts. Every list query in `loadBoard` goes through it in a fixed total order (`BOARD_ORDER`, which ends in the table's key). The web owns the TypeScript original in `src/vinnubord/lib/paging.ts`, the CLI a `.mjs` copy, and the parity test keeps them equal, like every other rule the CLI copies.

**Tech Stack:** TypeScript, supabase-js (PostgREST `Range` and `Prefer: count=exact`), vitest, plain Node ESM in `cli/`.

**Spec:** Huginn card `b610fdbd` on the board `metta` ("Huginn: borðið sækir mest 1000 raðir í töflu"). The card body is the requirement; the section "What was measured" below replaces its estimates with measurements. Huginn plan row: `1c63f91b`.

## Review Focus

Failure modes the card implies, most likely first. Each is pinned by a test in the task that owns the code.

1. **A list whose length is exactly a page (1000, 2000 rows).** A pager that asks for one more page gets HTTP 416 and fails the whole board. Expected: one request, no error. Test: "never asks past the end of a list of exactly one page" (Task 1).
2. **Rows that share `created_at` across a page boundary.** Without a unique last order column the same row can come on two pages and another on none. Expected: every row once. Test: "ends every order in the key of its list" (Task 1), and the reviewer of Task 2 checks that no list query in either `loadBoard` bypasses `ordered`.
3. **A page that fails in the middle of a list** (network drop on page two). Expected: the load fails as it does today, never a board built from the first 1000 rows. Test: "returns no rows when a later page fails" (Task 1).
4. **The list changes while it is read.** A row added between two pages must be read, and a list that shrank must not fail the board. Tests: "follows a list that grows between two pages", "keeps what it read when the list shrinks between two pages" (Task 1).
5. **The server cap is lowered below 1000** in the shared Supabase project. A "short page means the end" rule would then cut every list silently. Expected: everything is still read, because the count decides. Test: "reads everything when the server cap is below the page size" (Task 1).

The five web only lists (`hg_views`, the three view position tables, the `hg_unread` rpc) have no CLI copy and no smoke coverage. Task 2 Step 7 checks them in the browser.

## Known and accepted

- Offset pages are not a snapshot. For a list of more than 1000 rows, a row inserted earlier in the order between two pages (possible for `hg_plans`, ordered by `position`, and `hg_tags`, ordered by `name`) can appear twice in one load, and a row deleted between two pages can hide one row for one load. The next load is right. No dedupe is built.
- Every load now asks the server for an exact count per list. At these sizes the count costs less than the rows it counts.
- Lists are read whole, so they grow with the project: plans, rulings, files, actions and comments of items closed more than 90 days ago still load. Rulings grow by about 60 a day on metta, one more request roughly every 17 days. Bounding the child lists by the item window is a separate card, not this plan.

## Out of scope

- The `ROW_CAP` guard in `scripts/deals/huginn.mjs` in the fastaust repo (`boardProblem`). After this plan a list of 1000 rows or more is whole, and the guard would stop the mirror and the inbox for no reason. Removing it is a change in another repo: Task 3 records it as an action on the card.
- The 500 event limit and the 90 day item window.

```ts
import { describe, it, expect } from 'vitest'
import { BOARD_ORDER, MAX_PAGES, PAGE_SIZE, RANGE_PAST_END, TOO_MANY_ROWS, fetchAll, ordered, type Page } from './paging'

type Row = { id: number }
const rows = (n: number, start = 0): Row[] => Array.from({ length: n }, (_, i) => ({ id: start + i }))
const pastEnd = { message: 'Requested range not satisfiable', code: RANGE_PAST_END }

// A list of `total` rows behind a server that answers with at most `cap` rows
// and, like PostgREST, refuses an offset past the last row.
function table(total: number, { cap = PAGE_SIZE, count = true } = {}) {
  const calls: Array<[number, number]> = []
  const page = async (from: number, to: number): Promise<Page<Row>> => {
    calls.push([from, to])
    if (from > 0 && from >= total) return { data: null, error: pastEnd, count: null }
    const n = Math.max(0, Math.min(to + 1, total, from + cap) - from)
    return { data: rows(n, from), error: null, count: count ? total : null }
  }
  return { page, calls }
}

// A server that answers with the given pages in turn.
function scripted(pages: Page<Row>[]) {
  const calls: Array<[number, number]> = []
  const page = async (from: number, to: number): Promise<Page<Row>> => {
    calls.push([from, to])
    return pages[calls.length - 1]
  }
  return { page, calls }
}

describe('fetchAll', () => {
  it('reads an empty list in one request', async () => {
    const t = table(0)
    expect(await fetchAll(t.page)).toEqual({ data: [], error: null })
    expect(t.calls).toEqual([[0, 999]])
  })

    const t = table(282)
```

```ts
// How loadBoard reads its lists. PostgREST answers with at most 1000 rows per
// request and cuts the rest without an error (measured on the live project
// 2026-11-25), so every list is read in pages. The CLI copy is
// cli/lib/paging.mjs, kept equal by cli/lib/parity.test.mjs.

export const PAGE_SIZE = 1000
// 100 pages is 100 000 rows of one kind in one project: a runaway, not a board.
export const MAX_PAGES = 100
// PostgREST code for an offset past the last row (HTTP 416).
export const RANGE_PAST_END = 'PGRST103'
export const TOO_MANY_ROWS = `Fleiri en ${PAGE_SIZE * MAX_PAGES} raðir í einni töflu.`

// The fixed order of every list loadBoard pages through. Each ends in the
// table's key, so the order is total: rows written in one insert share
// created_at, and without the key one of them could land on two pages or none.
export const BOARD_ORDER = {
  hg_participants: ['created_at', 'id'],
  hg_packages: ['position', 'created_at', 'id'],
  hg_modules: ['position', 'created_at', 'id'],
  hg_items: ['created_at', 'id'],
  hg_plans: ['position', 'created_at', 'id'],
  hg_files: ['created_at', 'id'],
  hg_questions: ['created_at', 'id'],
  hg_actions: ['created_at', 'id'],
  hg_rulings: ['created_at', 'id'],
  hg_comments: ['created_at', 'id'],
  hg_reads: ['item_id', 'user_id'],
  hg_unread: ['item_id', 'kind'],
  hg_views: ['position', 'created_at', 'id'],
  hg_tags: ['name', 'id'],
  hg_view_positions: ['view_id', 'item_id'],
  hg_view_pack_positions: ['view_id', 'package_id'],
  hg_zones: ['created_at', 'id'],
  hg_view_zone_positions: ['view_id', 'zone_id'],
} as const

export type BoardList = keyof typeof BOARD_ORDER

export type PageError = { message: string; code?: string }
export type Page<T> = { data: T[] | null; error: PageError | null; count?: number | null }
export type AllRows<T> = { data: T[]; error: PageError | null }

// page(from, to) runs one query for the rows from..to (zero based, inclusive)
// in a fixed total order, with the exact count when the server gives one.
// A failed page fails the whole list: a board is never built from part of one.
export async function fetchAll<T>(page: (from: number, to: number) => PromiseLike<Page<T>>): Promise<AllRows<T>> {
  const rows: T[] = []
  for (let n = 0; n < MAX_PAGES; n++) {
    const res = await page(rows.length, rows.length + PAGE_SIZE - 1)
    if (res.error) {
      // The list shrank between two pages, so the rows already read are all of it.
      if (n > 0 && res.error.code === RANGE_PAST_END) return { data: rows, error: null }
      return { data: [], error: res.error }
    }
    const got = res.data ?? []
    for (const row of got) rows.push(row)
    if (got.length === 0) return { data: rows, error: null }
    // With a count the list is whole when it holds that many rows. Without one
    // a short page is the end. The next page starts after the rows received,
    // so a server cap below PAGE_SIZE still reads everything.
    const whole = typeof res.count === 'number' ? rows.length >= res.count : got.length < PAGE_SIZE
    if (whole) return { data: rows, error: null }
  }
  return { data: [], error: { message: TOO_MANY_ROWS } }
}

// Adds the fixed order of a list to a query, so two pages of it never overlap.
export function ordered<Q extends { order(column: string): Q }>(query: Q, list: BoardList): Q {
  let q = query
  for (const column of BOARD_ORDER[list]) q = q.order(column)
  return q
}
```

```js
    // a short page is the end. The next page starts after the rows received,
    // so a server cap below PAGE_SIZE still reads everything.
    const whole = typeof res.count === 'number' ? rows.length >= res.count : got.length < PAGE_SIZE
    if (whole) return { data: rows, error: null }
  }
  return { data: [], error: { message: TOO_MANY_ROWS } }
}

// Adds the fixed order of a list to a query, so two pages of it never overlap.
export function ordered(query, list) {
  let q = query
  for (const column of BOARD_ORDER[list]) q = q.order(column)
  return q
}
```
