# Tiltekt: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three tidying tools on the whiteboard: closed cards fade and stay three days before they leave, a pack column folds to one line per browser, and the cards of a Ctrl selection arrange into a grid with one undo.

**Architecture:** No migration. `isOpen` and `isOnBoard(item, now)` split in `lib/status.ts` and its CLI copy, with `CLOSED_LINGER_DAYS = 3`; a closed card has no count bucket, matches no tone filter, draws with `.hg-card-closed` and a parked wire, and lists last. Folding is a `localStorage` set per project (`lib/packs.ts`, `useCollapsedPacks`) that `Board` reads to leave the cards of folded packs undrawn, with a folded pack carrying its hidden cards along on a drop. Arranging is a pure `arrangeGrid` in `lib/arrange.ts` applied through the existing `onDrop` pipeline from a small bar that shows while two or more cards are selected.

**Tech Stack:** React 19 + TypeScript, vitest, react-i18next, Node ESM CLI with the parity test.

**Spec:** `docs/superpowers/specs/2026-11-04-kassar-og-tiltekt-design.md`, sections 4.4 to 4.6, 5, 6 and 8. Plan 15 (kassar) is built before this plan; this plan starts from main with plan 15 merged.

## Global Constraints

- No database change. The board already loads items closed in the last 90 days (`CLOSED_HISTORY_DAYS`).
- `hg_unread` returns open items only (0010b), so a closed card never glows and never carries a fresh line; nothing here changes that.
- **Never a coloured left border, stripe or bar** on a folded pack, the selection bar or a closed card.
- No em dashes or hyphen dashes as punctuation anywhere: code comments, copy, docs, commit messages. Commas, periods or colons. The middle dot `·` is allowed in the fold line.
- Icelandic UI copy. New i18n keys go in `en.json` by hand under `vinnubord.*`, `npm run translate` regenerates `is.json`, then check the `is.json` diff and set the Icelandic exactly as this plan gives it (keys alphabetical in `is.json`).
- Rules below the token block in `vinnubord.css` read only tokens. Tasks 4 and 7 add the tokens and rules of this plan verbatim; no other task adds CSS.
- Pure logic in `src/vinnubord/lib/` with a vitest file beside it; test files import from `vitest` explicitly. The CLI copies `isOpen`, `isOnBoard` and `CLOSED_LINGER_DAYS` in `cli/lib/status.mjs` and `parity.test.mjs` pins them.
- Folding, the selection bar and arranging never touch the database except through the existing position saves. Folding is per browser and never shared.
- The Ctrl selection and the selection bar are mouse only, as today.
- Branch `vinnubord-16` off `main` (after plan 15 is merged). Commit prefixes `feat(vinnubord):`, `fix(vinnubord):`, `test(vinnubord):`, `docs(vinnubord):`, `chore(vinnubord):`, with the `Co-Authored-By:` trailer of the model that authored the commit.
- `npm run build` and `npm run test` green at the end of every task.
- Implementer budget per task: about 60 tool calls or 150k context, then commit what is green and report DONE_WITH_CONCERNS. Read code in large ranges with Read, not sed slices.
- Model routing (global rules): Tasks 5 and 10 are transcription of code, copy and docs in this plan and go to Sonnet; Tasks 1, 2, 3, 4, 6, 7, 8 and 9 need judgment and go to Opus. Every code task gets a review (Opus), the final whole branch review runs on Fable.
- Each task names its verification set. The implementer checks nothing else; reviewers judge the whole diff.

## Review Focus

1. A closed item with `closed_at` null (never possible after 0003, but old rows and the CLI tests build such items): it is off the board, not on it forever. Pinned in Task 1 (`isOnBoard` test).
2. The "Í bið" pill with 3 parked items and 2 closed cards on the board: the pill says 3 and lights exactly those 3; the closed cards dim. Pinned in Task 3 (`cardModels` test) and Task 2 (`matches` test).
3. A folded pack dragged inside a view and dropped: its hidden cards get a `hg_view_positions` row each with the same delta, and `hg_items.pos_x` of those cards does not move. Pinned in Task 7 (manual check 4).
4. A list row pick of a card in a folded pack: the pack opens, the board glides to the card and the panel opens, in that order, with no frame where `reveal` ran before the card existed. Pinned in Task 7 (manual check 2).
5. Raða on a selection that holds one card and two packs: nothing moves and the bar does not show (the bar needs two cards); Raða with five cards then Afturkalla after a card was dragged by hand: the dragged card returns too (undo restores every recorded position). Pinned in Task 9 (manual checks 3 and 5) and Task 8 (`arrangeGrid` test for one box).
